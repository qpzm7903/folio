## 1. `No Hmos SDK found` — build 和 doctor 的 SDK 检测不是一套

`flutter doctor` 认 `OHOS_SDK_HOME` (OpenHarmony 布局) 就给绿灯, 但
`flutter build hap` 走 `hvigor_utils.dart` 硬性要求 **HmosSdk**
(`HOS_SDK_HOME` / `DEVECO_SDK_HOME`)。

修法 (不下载 HarmonyOS SDK, 伪装布局): `HOS_SDK_HOME` 指向一个目录,
其子目录含 `sdk-pkg.json` 即可通过校验:

```bash
mkdir -p ~/sdks/hos-sdk
ln -sfn ~/sdks/ohos-sdk/sdk/20 ~/sdks/hos-sdk/20
printf '{"data":{"apiVersion":"20","version":"6.0.0.47"}}\n' \
  > ~/sdks/ohos-sdk/sdk/20/sdk-pkg.json
export HOS_SDK_HOME=~/sdks/hos-sdk
```

## 2-4. hvigor 模块解析三连坑 (本篇核心)

fork 的构建桥接是: `ohos/hvigorconfig.ts` → import `flutter-hvigor-plugin`
(fork 内的 TS 插件) → import `@ohos/hvigor-ohos-plugin`。三个坑:

**坑 A — flutter create 生成的工程没有 hvigorw wrapper**。官方 DevEco 的
hvigorw 负责读 `hvigor/hvigor-config.json5` 并把依赖装进缓存; 自己用 npm
装的裸 hvigor 没有这个自举, `hvigor-config.json5` 里写依赖也**不会**被安装。

**坑 B — flutter_tools 每次构建重写 `ohos/package.json` 并 npm install**
(`installHvigorPlugin`), 只装 `flutter-hvigor-plugin` 一个 file: 依赖,
还会把你手动放在 `ohos/node_modules` 的东西/符号链接清掉。

**坑 C — 模块双实例 = `TypeError this.getInstance is not a function`**。
如果 `@ohos/hvigor` 在运行核心和插件各自的 node_modules 里有两份拷贝,
hvigor 的单例状态会碎掉, 报这个毫无指向性的 TypeError。
(node 按 realpath 缓存模块, file: 依赖是 symlink, 解析回真实路径后
找的是**插件目录自己**的 node_modules。)

统一修法 — **全局唯一一份 hvigor node_modules, 其余位置全部符号链接**:

```bash
# 1. 全局安装核心 + 插件 (版本要配对, 见下节)
cd ~/sdks/hvigor
npm install --legacy-peer-deps @ohos/hvigor@5.19.8 @ohos/hvigor-ohos-plugin@5.19.8
# 2. fork 插件目录 → 链到全局 (解析 @ohos/hvigor 时同 realpath = 单实例)
ln -s ~/sdks/hvigor/node_modules \
  ~/sdks/flutter-ohos/packages/flutter_tools/hvigor/node_modules
# 3. 仓库根 → 链到全局 (ohos/node_modules 会被 flutter 清写, 但 node 向上
#    逐级找, 根目录这层 flutter 不碰)
ln -s ~/sdks/hvigor/node_modules <repo>/node_modules   # 记得 gitignore
```

## 5. hvigor 版本怎么选

- fork 的 `flutter_tools/hvigor/package.json` 写着 devDep `@ohos/hvigor 5.2.2`
  — **过时了**, 5.2.2 根本不支持模板里的 `hvigorconfig.ts`
  ("The hvigorConfig is not yet available for build")。
- 6.24.2 (最新) 过新, 内部 API 对不上。
- **5.19.8 (5.x 最末版) 实测可用**, 与模板 `modelVersion: 5.1.0` 同代。
- npm 装 @ohos 包必须 scope 路由:
  `--registry=https://registry.npmjs.org --@ohos:registry=https://repo.harmonyos.com/npm/`
  (全华为源 → postcss 等传递依赖 404; 全 npmjs → 没有 @ohos 包),
  且要 `--legacy-peer-deps` (fork 的 package.json 钉死旧版导致 ERESOLVE)。

## 6. OpenHarmony 工程的 build-profile 五连改

模板默认按 HarmonyOS 生成, 用免登录 OpenHarmony SDK 要逐项改:

| 文件 | 字段 | 模板值 | 改为 |
|------|------|--------|------|
| ohos/build-profile.json5 | products[0].runtimeOS | "HarmonyOS" | "OpenHarmony" |
| ohos/build-profile.json5 | products[0].compatibleSdkVersion | "5.1.0(18)" | 20 (整数) |
| ohos/build-profile.json5 | products[0].compileSdkVersion | (无) | 20 (OpenHarmony 必填) |
| ohos/entry/build-profile.json5 | targets[0].runtimeOS | "HarmonyOS" | "OpenHarmony" |
| ohos/entry/src/main/module.json5 | deviceTypes | ["phone"] | ["default", "tablet"] |

另外 hvigor 需要 `export OHOS_BASE_SDK_HOME=~/sdks/ohos-sdk/sdk`。

- `compileSdkVersion/compatibleSdkVersion` 在 OpenHarmony 工程里是**整数**
  (HarmonyOS 工程才是 "5.1.0(18)" 字符串格式)。
- **deviceTypes 没有 "phone"**: OpenHarmony 的 device-define 只有
  default / tablet / tv / wearable / 2in1 / liteWearable, 手机就是 `default`。
- **bundleName 必须至少三段** (schema `(\.x){2,}`): `app.folio` 不合法,
  鸿蒙端只能用 `app.folio.ohos` — 跟 Android/iOS 包名规范的硬差异。
