### 踩坑: form_config.json 是严格 JSON, 不能带 `//` 注释键

首次构建 `hvigor ERROR: BUILD FAILED` (883ms), 报:
```
keyword: 'propertyNames', params: { propertyName: '//updateDuration' },
message: 'property name must be valid'
```
form_config.json 走 JSON schema 校验, `forms[].` 只允许声明字段
(name/src/updateDuration/metadata/... 见报错里的 allowed 列表), 自加的
`"//xxx"` 文档键会被判非法属性名。**form_config.json 里别写 `//` 注释**,
说明文字放 ADR / 本 wiki。删掉两处 `//` 键后构建即过。

## 未决风险 (真机验证重点核对)

1. **form 能力 import 路径**: scaffold 用了 HarmonyOS NEXT 的 `@kit.FormKit`
   / `@kit.AbilityKit`。OpenHarmony 6 fork 上若报 `Cannot find module`,
   改回 `@ohos.app.form.FormExtensionAbility` / `@ohos.app.form.formBindingData`
   / `@ohos.app.ability.Want` 这套 `@ohos.*` 路径。两套二选一, 真机首编即知。
2. **卡片页 ArkTS 子集**: form 卡片对可用组件/语法有裁剪 (与普通页面不同)。
   `postCardAction` / `@LocalStorageProp` 是 form 专用 API, 若编译报错按
   OpenHarmony form 文档调整。
3. **fork 是否支持 FormExtensionAbility**: 鸿蒙化 Flutter fork 主要保证
   UIAbility 跑 Flutter 引擎, FormExtensionAbility 是纯 ArkTS、不嵌引擎,
   理论上与 Flutter 无关、应能独立注册; 但 fork 的工程模板/构建链是否完整
   支持 extensionAbilities 需真机证实。若不支持, 退回 ADR 0002 备选评估。
4. **数据桥 (里程碑②) 的 channel 注册**: 计划在 `EntryAbility.ets` 自写
   `app.folio/ohos_widget` MethodChannel (非 pub 插件, 绕开上游 #1)。这条
   能否在 fork 上注册成功是 ADR 0002 的核心假设, 里程碑② 落地时验证。
