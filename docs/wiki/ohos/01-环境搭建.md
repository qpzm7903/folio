# 鸿蒙适配 Wiki · 01 环境搭建 (macOS, 不装 DevEco Studio)

> Folio L20 里程碑① 的过程记录。目标: 在 macOS (Apple Silicon) 上零 DevEco
> 搭起 Flutter → HarmonyOS 6.0 (Mate 80) 的构建链。
> 本篇面向对外分享, 所有步骤可复现, 不含任何账号/证书信息。

## 结论速览

| 组件 | 版本 | 来源 | 需要华为账号? |
|------|------|------|--------------|
| Flutter 鸿蒙化 fork | 3.35.8-ohos-1.0.1 (tag) | gitcode CPF-Flutter/flutter_flutter | 否 |
| OpenHarmony SDK | 6.0-Release (API 20) | repo.huaweicloud.com 公开镜像 | 否 |
| ohpm | 5.0.2 (oh-command-line-tools) | repo.huaweicloud.com 公开镜像 | 否 |
| hvigor | 项目内 hvigorw 自举 | npm registry | 否 |
| 调试签名 (p12/cer/p7b) | — | AGC 网页控制台 | **是 (唯一需要账号的环节)** |

关键发现: **构建链全程不需要 DevEco Studio, 也不需要登录华为账号**。
官方 Command Line Tools 下载页要登录, 但华为云公开镜像
`repo.huaweicloud.com` 上有全部等价物。

## 1. Flutter 鸿蒙化 fork

仓库已从 openharmony-sig / openharmony-tpc 整体迁移到 **CPF-Flutter** 组织
(旧仓暂时还在同步, 但新工作应指向新组织):

```bash
git clone https://gitcode.com/CPF-Flutter/flutter_flutter.git ~/sdks/flutter-ohos
cd ~/sdks/flutter-ohos
git checkout 3.35.8-ohos-1.0.1   # 选正式 tag, 不要直接用分支 HEAD
```

踩坑:
- **分支命名是 `oh-x.y.z-release`**, 不是 `x.y.z-ohos`。正式版本打 tag
  (如 `3.35.8-ohos-1.0.1`), 1.0.2-debug / 1.0.3-beta 这类后缀不是稳定版。
- **必须 checkout tag 而不是浅克隆分支 HEAD**: 浅克隆没有 tag 时
  `flutter --version` 显示 `0.0.0-unknown`, pub 解析 `flutter: ">=3.27.0"`
  这类 SDK 约束会直接失败。
- fork 和官方 SDK 必须各自独立安装, 用 PATH 前缀切换:
  `export PATH="$HOME/sdks/flutter-ohos/bin:$PATH"` (鸿蒙) /
  `flutter-stable` (主线)。两者共用 `PUB_CACHE` 没问题。
- 国内镜像加速: `PUB_HOSTED_URL=https://pub.flutter-io.cn`,
  `FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`。

## 2. OpenHarmony SDK (免登录公开镜像)

官方路径 (developer.harmonyos.com 的 Command Line Tools) 需要登录, 但
OpenHarmony 每个 Release 的 SDK 在华为云镜像完全公开:

```bash
# 列出所有版本: https://repo.huaweicloud.com/openharmony/os/
# 6.0-Release = API 20, 对应 HarmonyOS 6.0 (Mate 80)
curl -L -o L2-SDK-MAC-M1-PUBLIC.tar.gz \
  https://repo.huaweicloud.com/openharmony/os/6.0-Release/L2-SDK-MAC-M1-PUBLIC.tar.gz
```

- Apple Silicon 选 `L2-SDK-MAC-M1-PUBLIC.tar.gz`, Intel 选
  `ohos-sdk-mac-public.tar.gz`, Linux/Windows 选
  `ohos-sdk-windows_linux-public.tar.gz`。
- Flutter fork 识别 SDK 的环境变量优先级: `flutter config --ohos-sdk` >
  `OHOS_HOME` > `OHOS_SDK_HOME` (纯 OpenHarmony SDK), 或
  `HOS_SDK_HOME` / `DEVECO_SDK_HOME` (HarmonyOS/DevEco 布局)。
- 目录布局要求: `$OHOS_SDK_HOME/<api数字>/toolchains/hdc` 必须存在
  (fork 会自动多试一层 `<dir>/sdk`)。SDK 包解出来的 ets/js/native/
  previewer/toolchains 若是 zip 需要逐个解开摆成 `20/{ets,js,...}`。
- `hdc` (设备调试桥, 等价 adb) 就在 SDK 的 `toolchains/` 里, 不用单独装。

## 3. ohpm (免登录) + hvigor

ohpm 是 node 脚本型 CLI, 跨平台, 华为云镜像直接有:

```bash
# https://repo.huaweicloud.com/harmonyos/ohpm/
curl -L -o oh-clt.zip \
  https://repo.huaweicloud.com/harmonyos/ohpm/5.0.2/oh-command-line-tools-20240715.zip
unzip oh-clt.zip && chmod +x oh-command-line-tools/{bin,ohpm/bin}/*
export PATH="$PWD/oh-command-line-tools/ohpm/bin:$PATH"
ohpm -v   # 5.0.2
```

- 同目录 5.0.3/5.0.5/5.1.0 只有 linux-x64 的完整 commandline-tools;
  20240715 这个老包是纯 node 实现, macOS 直接可用。
- hvigor 不用预装: DevEco/Flutter 工程内置 `hvigorw` wrapper, 首次构建
  时按工程 `hvigor/hvigor-config.json5` 里钉的版本从 npm registry 自举。
- 镜像上还有 `hapsigntoolv2.jar` (develop_tools/), 手动签名备用。

## 4. 主线开发环境同场踩坑 (Flutter 3.44.2)

- 本地 SDK 比 CI 新两个 minor 时, `flutter analyze` 会多报新 lint
  (unnecessary_import / prefer_const_declarations 等), `dart format` 是
  3.44 tall-style 会重排大量文件 — CI 把 format 设为 apply-only、
  analyze 加 `--no-fatal-infos` 可以解耦本地/CI 版本差。
- drift 的 `*.g.dart` 不进仓库: 新机器 clone 后必须先
  `dart run build_runner build`, 否则 analyze 报
  `QuotesDatabase.close 未定义` 这种误导性错误。
